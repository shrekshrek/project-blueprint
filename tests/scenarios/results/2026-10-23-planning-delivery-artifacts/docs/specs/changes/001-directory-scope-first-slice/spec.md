# 001 目录关系到查看范围首片

创建于 2026-10-23 · 状态：首片已实现，等待用户反馈

## 做什么
依照已批准 [Blueprint](../../../blueprint/handoff.yaml) v0.2.0 的 SLC-001，把合成名单变成目录持有的稳定关系，应用用公开快照显示本人及直属下属，超管可调整、撤销、恢复跟随和重导入。起点仅有名单文件，没有关系与访问引擎；当前实现状态见 [current](../../current.md)。新交付是本地 Node 无依赖页面及可测试模块；不部署、不接真实数据、不改认证；部门授权 SLC-002 不在本片。

用户在模拟回复中明确：“接受这份方案和页面操作方向。确认人工调整/显式撤销优先，只有明确恢复跟随导入才恢复；目录维护也仅超管；发布后下一读最新完整快照，无有效快照拒绝查询。接受所列合成验收、审计及本地边界。”并要求通过 feature-init 开始开发，但“本轮没有授予跨阶段连续执行权限”。该回复使旧规划阶段禁止实现被当前临时项目首片授权取代。

## 方案与依据
继承 CT-IDENTITY、CT-SCOPE、CT-BOUNDARY、CT-SNAPSHOT、D-IMPORT、D-ADMIN、D-CONSISTENCY、D-AUDIT；原始定义在 [plan](../../../blueprint/plan.md)，不在这里另立规则。目录拥有身份、部门、导入关系、人工覆盖、审计与版本；应用只读完整稳定ID快照，拒绝不可用或无效快照。单进程内原子提交候选状态与审计；每次读取获取当前快照，无缓存。维护输入 expectedRevision 防止旧页面覆盖；按批次重复提交保持幂等，批次同ID不同内容拒绝。
本地页面展示合成身份选择，服务端固定的 SYN 角色映射供试验，不是身份认证；不可把请求体的 isSuper 当权限。所有维护命令检查该合成主体的超管角色，普通主体即使直接调用也拒绝。入口只监听本地回环，SYN 标识之外拒绝。运行状态内存保存，重启恢复 fixture；这是已接受合成本地试验的实现，不增加持久数据库。当前原型本身仍只是决策辅助。
目录导入先预览再发布；经理名唯一匹配后转稳定 ID，未知/同名/环导致整批拒绝，旧快照保留；名单缺失需显式确认停用才发布。人工覆盖优先；恢复跟随也验证完整关系。审计可从页面查看维护者、时间、前后、批次；保留期依上游仅在真实接入前决定。本片回滚边界是整个本地进程及 src/test 新文件，无真实数据迁移。

## 怎样验收
先走最短用户链：打开本地页面，Alex仅见本人和Bo；用超管撤销Bo上级，重导入后Alex仅本人；恢复跟随后Alex再见Bo。增加SYN-P4直属于Bo，Alex不见其孙级；超管看到全部。
`node --test` 验证导入到应用链路，以及同名不误配、循环/自管、重复批次幂等、相同ID不同批次内容拒绝、缺失显式停用、人工覆盖重导入不复活、恢复成环拒绝、版本冲突不覆盖、普通人直接维护拒绝、无快照或无效快照拒绝、审计可回溯；HTTP测试验证页面/API与服务端身份适配连通。无需外部或昂贵检查。
父任务已观察原型2→5→2→1人流程，只用于接受方向，不替代本实现证据。页面为读者展示范围，也为超管展示关系变更与导入差异，不提前做部门授权。

## 实施与反馈停点
顺序：公开目录关系快照与访问判定→本地页面维护/查看→同一首片的最小检查。对用户交接可检查页面、实际输出与验证，不以文件层为停点。首片结束等待反馈，不能因测试通过或“开始开发”而进入 SLC-002。出现所有权、真实持久化、认证、撤销延迟或验收变化，先停受影响工作回到上游。
